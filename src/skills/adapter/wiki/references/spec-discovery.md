# Workflow «spec-discovery»

Поиск зафиксированной спецификации для issue. Вход: нормализованный текст
issue, его явные ссылки, данные связанного эпика (название,
описание, ссылки), проект/компонент. Явные ссылки включают remote links
(панель Links) — их этот адаптер не читает, вызывающий берёт их у адаптера
трекера и передаёт как часть входа. Источники — строго по порядку,
детерминированные первыми:

1. явные wiki-ссылки в самой issue (описание, remote links);
2. ссылки из связанного эпика (описание, remote links);
3. конфиг-маппинг проект/компонент → пространства/корневые страницы
   (`docs_wiki.spec_roots`);
4. полнотекстовый поиск: первым запросом — название связанного эпика,
   затем summary issue и компонент.

Исключённые поддеревья. Корни из `docs_wiki.spec_exclude` карты периметра и всё их поддерево на любой глубине из дискавери исключены: такую страницу не читай, источником не регистрируй и в список гейта не выводи. Принадлежность проверяй по цепочке предков — `ancestors <id|url>` отдаёт цепочку и ставит в `excluded_by` id корня, под которым лежит страница. Заголовок признаком не служит: страницы исключённого поддерева называются так же, как спецификация.

Гейт на источники, не названные задачей. Источники 3 и 4 находят страницы, которых сама задача не называет, — среди них попадаются черновики. После составления списка кандидатов и до чтения любого из них предъяви пользователю ссылками все страницы из источников 3 и 4 и дождись явного утверждения. Гейт блокирующий: неутверждённая страница не читается и источником не регистрируется; отклонённая страница исчерпывает свой источник наравне с пустым результатом. Страницы источников 1 и 2 гейта не требуют — их называет сама задача.

Дедуп: одна страница часто приходит из нескольких источников (тело, remote
links, полнотекстовый поиск). Идентифицируй страницу по page id, а не по URL:
один id приходит как `pageId=<id>`, `/pages/<id>/…` и `/display/…#<якорь>`.
URL без page id в самой ссылке (например форма `/display/…`) разреши в page id
через `page <url>` (`metadata.id`). Страницу, уже зарегистрированную из более
раннего источника, при повторном появлении не регистрируй и не перечитывай.

Найденная страница часто лишь обзор-родитель: контрактные детали (методы/API,
функциональные требования, сценарии использования, атрибуты) вынесены в
дочерние/листовые страницы. После её нахождения обойди дочерние страницы
(готовой команды нет — через `call` инструментом получения дочерних страниц или
дерева пространства), отбери по заголовкам содержательные и зарегистрируй
наравне с родительской: обзор их не заменяет.

Исходы:

- **found** — список страниц спецификации; для каждой зафиксируй URL,
  page id, номер версии, дату версии и отметку последнего активного
  комментария — дату, а при пустых датах сервера — `open_count`/`max_id` из
  сводки `summary` команды `comments` (вложения не отслеживаются). Маркером
  свежести и основанием открытого вопроса автору служит только активный
  комментарий: закрытое обсуждение (`resolution` — `resolved` или `dangling`)
  читатель на странице не видит, и `comments` по умолчанию его не отдаёт —
  полный список возвращает `--include-resolved`, счётчик закрытых стоит в
  `closed_count`. Статусы, пришедшие как `unknown`
  (`resolution_source: "unavailable"`), открытость обсуждения не устанавливают —
  свежесть по ним фиксируй как неустановленную. Страница с усечённым телом не считается
  прочитанной (см. правило об обрезанном теле): нельзя регистрировать её
  как источник и подменять незахваченные правила спецификации
  формулировками issue;
- **confirmed-absent** — допустим только после исчерпания всех четырёх
  источников;
- **wiki-unavailable** — сервис недоступен, не сконфигурирован или выключен
  (`docs_wiki.product = "none"`, пустой `docs_wiki`);
  недоступность не равна отсутствию спецификации, вывод
  `confirmed-absent` в этом случае запрещён.

Перепроверка актуальности найденных страниц — `page <id> --body none`:
рост номера версии (покрывает заголовок и содержимое) или новая отметка
активных комментариев (дата, при пустых датах — `open_count`/`max_id` сводки
`comments`) означает, что страницу надо перечитать.
