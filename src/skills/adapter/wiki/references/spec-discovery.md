# Workflow «spec-discovery»

Поиск зафиксированной спецификации для issue. Вход: нормализованный текст issue, её комментарии, явные ссылки и связи с другими объектами Jira.
Явные ссылки включают remote links (панель Links) — их этот адаптер не читает, вызывающий берёт их у адаптера трекера и передаёт как часть входа.

По умолчанию используй только источники, которые названы в Jira или явно разрешены пользователем, включая постоянное пользовательское или проектное правило. Источники проверяй в таком порядке:

1. явные wiki-ссылки в самой issue: описание, комментарии и remote links;
2. явные wiki-ссылки из эпика или связанных issues, если связь с ними указана в исходной issue;
3. страницы, явно названные пользователем или разрешённые действующим пользовательским либо проектным правилом.

Без явной команды пользователя не обращайся к `docs_wiki.spec_roots`, не выполняй полнотекстовый поиск спецификаций и не предлагай найденные таким образом страницы.
Команда пользователя на расширенный поиск разрешает дополнительные источники в таком порядке:

4. конфиг-маппинг проект/компонент → пространства/корневые страницы (`docs_wiki.spec_roots`);
5. полнотекстовый поиск: первым запросом — название связанного эпика, затем summary issue и компонент.

Исключённые поддеревья. Корни из `docs_wiki.spec_exclude` карты периметра и всё их поддерево на любой глубине из дискавери исключены: такую страницу не читай, источником не регистрируй и в список гейта не выводи.
Принадлежность проверяй по цепочке предков — `ancestors <id|url>` отдаёт цепочку и ставит в `excluded_by` id корня, под которым лежит страница.
Заголовок признаком не служит: страницы исключённого поддерева называются так же, как спецификация.

Гейт расширенного поиска. Если пользователь разрешил только найти дополнительные источники, но не разрешил их использовать, после составления списка кандидатов покажи страницы ссылками и дождись явного утверждения до чтения.
Если команда прямо разрешает найти и использовать дополнительные источники, отдельный гейт не нужен.
Неутверждённая страница не читается и источником не регистрируется; отклонённая страница исчерпывает свой источник наравне с пустым результатом.
Источники 1–3 отдельного гейта не требуют: их уже называет Jira или явно разрешает пользователь.

Дедуп: одна страница часто приходит из нескольких источников (тело, remote
links, полнотекстовый поиск). Идентифицируй страницу по page id, а не по URL:
один id приходит как `pageId=<id>`, `/pages/<id>/…` и `/display/…#<якорь>`.
URL без page id в самой ссылке (например форма `/display/…`) разреши в page id
через `page <url>` (`metadata.id`). Страницу, уже зарегистрированную из более
раннего источника, при повторном появлении не регистрируй и не перечитывай.

Найденная страница часто лишь обзор-родитель: контрактные детали (методы/API, функциональные требования, сценарии использования, атрибуты) вынесены в дочерние/листовые страницы.
Обходи дочерние страницы только когда пользователь явно разрешил расширенный поиск источников.
Используй `call` с инструментом получения дочерних страниц или дерева пространства, отбери по заголовкам содержательные страницы и зарегистрируй наравне с родительской: обзор их не заменяет.

Исходы:

- **found** — список страниц спецификации; для каждой зафиксируй URL,
  page id, номер версии, дату версии и отметку последнего активного
  комментария — дату, а при пустых датах сервера — `open_count`/`max_id` из
  сводки `summary` команды `comments` (вложения не отслеживаются). Маркером
  свежести и основанием открытого вопроса автору служит только активный
  комментарий: закрытое обсуждение (`resolution` — `resolved` или `dangling`)
  читатель на странице не видит, и `comments` по умолчанию его не отдаёт —
  полный список возвращает `--include-resolved`, счётчик закрытых стоит в
  `closed_count`. Статусы, пришедшие как `unknown`
  (`resolution_source: "unavailable"`), открытость обсуждения не устанавливают —
  свежесть по ним фиксируй как неустановленную. Страница с усечённым телом не считается
  прочитанной (см. правило об обрезанном теле): нельзя регистрировать её
  как источник и подменять незахваченные правила спецификации
  формулировками issue;
- **confirmed-absent** — допустим после исчерпания всех разрешённых источников. Не разрешённые пользователем `docs_wiki.spec_roots`, полнотекстовый поиск и дочерние страницы не входят в обязательный обход и не мешают этому исходу;
- **wiki-unavailable** — сервис недоступен, не сконфигурирован или выключен
  (`docs_wiki.product = "none"`, пустой `docs_wiki`);
  недоступность не равна отсутствию спецификации, вывод
  `confirmed-absent` в этом случае запрещён.

Перепроверка актуальности найденных страниц — `page <id> --body none`:
рост номера версии (покрывает заголовок и содержимое) или новая отметка
активных комментариев (дата, при пустых датах — `open_count`/`max_id` сводки
`comments`) означает, что страницу надо перечитать.
