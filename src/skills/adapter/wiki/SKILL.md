# Docs wiki

Работает с wiki-документацией по параметру `docs_wiki.product` (по
умолчанию — `confluence`): ищет и читает страницы, комментарии и
метаданные версий. Используй для URL wiki-страницы, поиска спецификации,
сверки требований с документацией; не используй для задач трекера и MR
хоста.

## Границы

- Обязательно: без точной команды `/external-write wiki <действие> <цель>` работай с wiki только в режиме read-only. Обычная подкоманда `call` технически отклоняет инструмент, у которого MCP-сервер не объявил `annotations.readOnlyHint=true`; для разрешённой записи используй только отдельную подкоманду `write-call`.
- Режим `docs_wiki.product = "none"`: внешней wiki нет — spec-дискавери не
  выполняется, сетевых вызовов не делай, источники требований передаёт
  вызывающий. Пустое значение `product` и отсутствие секции `docs_wiki`
  выключают адаптер так же. Клиент в этом режиме отказывает кодом 2, не
  открывая соединения: код 2 означает выключенный адаптер, а не битые креды.
- Используй on-demand клиент `WIKI_CLIENT="$AGENT_SKILLS_DIR/adapter-wiki/scripts/wiki.py"`; путь через установленный симлинк одинаков для всех CLI. Не регистрируй
  MCP-сервер wiki в конфигурации агента (держи `mcp_servers.*`
  выключенным, в `enabled = false`).
- Вызывай `python3 "$WIKI_CLIENT" …` из рабочего каталога проекта: конфигурация
  и секреты принадлежат периметру, а он резолвится по рабочему каталогу
  (`AGENTS_PROJECT_PATH` или `AGENTS_PROJECT` задают его явно). Вызов из
  каталога навыка читает общий периметр и не видит конфигурацию целевого проекта.
- Доступ к серверу (URL, заголовки, токен) — секция `[mcp.<продукт>]` файла
  секретов периметра; заполнение и проверка —
  `../references/credentials.md`. Ошибка авторизации или отсутствие секции —
  блокер конфигурации: сообщи и остановись, заголовки сам не подбирай.
- Создание, изменение и комментирование страниц разрешены только точной командой `/external-write wiki <действие> <цель>` и только для названных действия и цели.
- При чтении разрешённого содержимого страниц используй исходный вид
  (storage), не полагайся на markdown-конвертацию для связанных страниц:
  она теряет `ri:page`-ссылки; обходи их явно.
- Ссылки на страницы Confluence в пользовательском выводе показывай с названием страницы как видимым текстом ссылки; `pageId` и `page_id` используй только как технические идентификаторы и не показывай пользователю вместо нормального имени.
- Спецификацию читай в её последней доступной версии.
  Ссылаясь на неё в любом тексте — ответе, задаче, чек-листе, ADR, finding — приводи полный URL страницы; page id, короткое название и номер версии ссылку не заменяют.
  Записанный номер версии служит маркером изменений для следующей сверки, а не закрепляет редакцию требования; фиксируй редакцию как канон только по явному решению человека.

## Операции

Клиент `scripts/wiki.py` предоставляет классовые операции:

- `page <id|url>` — страница с метаданными версии (`version`, дата
  изменения); `--body storage|markdown|none` управляет форматом
  содержимого (`none` — только метаданные, дешёвая перепроверка версии;
  тело отбрасывается на клиенте — сетевой запрос остаётся полным).
- `search <запрос>` — полнотекстовый поиск; `--spaces` ограничивает
  пространства (по умолчанию из `docs_wiki.spaces`).
- `comments <id|url>` — активные комментарии страницы с локальной сводкой
  `summary` `{count, open_count, closed_count, max_id, latest_date,
  resolution_source}`. Статус резолюции каждого комментария — в поле
  `resolution`, дата его версии — в `date`; закрытые обсуждения (`resolved`,
  `dangling`) в вывод не идут, `--include-resolved` возвращает их с тем же
  полем. Маркер свежести (`max_id`, `latest_date`) считается по активным
  комментариям: закрытое обсуждение открытым вопросом не является. Часть
  серверов MCP отдаёт `created`/`updated` пустыми на всех инструментах (SB-23) —
  тогда маркер свежести это `open_count` + `max_id` (id контента монотонно
  растут); `count` считает все комментарии страницы и маркером не служит.
  Статусы и даты читаются прямым REST-GET (эндпоинт дочерних комментариев
  страницы), переиспользующим заголовки MCP-шлюза
  (`docs_wiki.rest.url_header`, `docs_wiki.rest.token_header`).
  `resolution_source: "unavailable"` означает недоступный канал статусов: они
  приходят как `unknown`, вывод не фильтруется, причина — в `resolution_error`;
  в таком выводе закрытое обсуждение от открытого не отличить.
- `ancestors <id|url>` — цепочка предков страницы сверху вниз (`id`, `title`) и `excluded_by`: id корня из `docs_wiki.spec_exclude`, под которым лежит страница, либо `null`. Цепочка читается прямым REST-GET: предков не отдаёт ни один MCP-инструмент.
- `tools` / `call <tool>` — список инструментов и универсальный read-only вызов, когда готовой команды нет; `call` допускает только инструменты с префиксом из `docs_wiki.tool_prefix` и явным `annotations.readOnlyHint=true`.
- `write-call <tool>` — отдельный универсальный Write-вызов; используй его только после точной команды `/external-write wiki <действие> <цель>` и только в её границах.

Дельту между редакциями страницы бери у хоста, а не сравнением сохранённых
дампов: `call <prefix>get_page_diff` (`page_id`, `from_version`,
`to_version`) отдаёт готовый diff, `call <prefix>get_page_history`
(`page_id`, `version`) — тело названной версии. Дамп прошлой редакции
переживает не каждый прогон, а diff хоста от его наличия не зависит и
разбора storage-XML не требует.

Объёмный ответ записывай через `--output` (подтверждение — `saved: <путь>`),
не повторяй запрос при обрезанном stdout; у подкоманды `call` этого флага
нет — перенаправляй её вывод в файл.

Обрезанное тело страницы (маркер усечения в ответе, оборванная разметка
или таблица) — это непрочитанная страница, а не «достаточно контекста»:
перечитай её с `--output` в файл; если полное тело так и не получено,
явно скажи об этом вызывающей стороне и не выдавай усечённый текст за
содержимое страницы.

## Workflow «spec-discovery»

Поиск зафиксированной спецификации для issue (источники из Jira и явных разрешений пользователя, расширенный поиск только по прямой команде, исключённые поддеревья, исходы `found`/`confirmed-absent`/`wiki-unavailable`, перепроверка актуальности) — `references/spec-discovery.md`.

## Ошибки

- Если инструмент вернул `isError`, не интерпретируй content как
  успешный результат.
- При ошибке авторизации или конфигурации сообщи сервер, операцию и
  безопасный текст ошибки; не выводи HTTP headers и токены.
- Не включай зарегистрированный MCP как workaround: это изменит поведение
  всех следующих сессий.
