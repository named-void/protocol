# Доступ адаптеров к MCP-серверу

## Где

Секция `[mcp.<продукт>]` находится в файле секретов периметра
`<data-root>/config.toml`; путь переопределяется `$AGENTS_SECRETS`. Имя
продукта задаёт соответствующая карта: `issue_tracker.product` или
`docs_wiki.product`.

```toml
[mcp.<продукт>]
url = "https://<mcp-gateway>/mcp"
http_headers = { "<Header-Product-Url>" = "https://<product-host>", "<Header-Personal-Token>" = "<token>", "<Header-User>" = "<user>" }
```

Файл лежит в `.data` носителя вне Git. Заполненную копию не коммить и не
пересылать: `http_headers` содержит личный токен. Шаблон с именами заголовков
конкретных продуктов находится в `secrets.example.toml` репозитория.

## Общие параметры

- `url` — адрес MCP-шлюза, не самого продукта.
- `http_headers` — требуемые шлюзом адрес продукта, личный токен и
  пользователь запросов. Набор заголовков бери из документации шлюза.
- Токен выпускается в разделе personal access tokens самого продукта.
- Требование минимальных прав проверяется организационно: продукты не отдают
  надёжные метаданные прав токена. Используй отдельный токен на периметр с
  коротким сроком жизни.

## Параметры адаптеров

### Issue tracker

- Минимальные права — чтение задач и комментариев. Права записи нужны только
  для явно запрошенных status transition и публикации комментария.
- Заголовки прямого REST-чтения remote links задают
  `issue_tracker.rest.url_header` и `issue_tracker.rest.token_header`; значения
  берутся из `http_headers`.

### Docs wiki

- Минимальные права — чтение страниц и комментариев. Права записи выдавай
  только периметру, где пользователь явно запрашивает разрешённые операции
  записи.
- `docs_wiki.product = "none"`, пустой `product` или отсутствующая секция
  `docs_wiki` выключают адаптер; секция `[mcp.*]` ему не нужна.
- Заголовки прямого REST-чтения статуса комментариев задают
  `docs_wiki.rest.url_header` и `docs_wiki.rest.token_header`; значения берутся
  из `http_headers`. Если заголовков нет, `comments` возвращает статус
  `unknown`.

## Проверка

- `python3 "$PROTOCOL_SRC/scripts/check-mcp.py"` проверяет все серверы и
  печатает `ok: … reachable` либо `fail:` с причиной, не раскрывая URL,
  заголовки и токены. `PROTOCOL_SRC` разрешается по правилу `AGENTS.md`.
- `python3 "$AGENT_SKILLS_DIR/adapter-issues/scripts/tracker.py" tools`
  проверяет живой доступ к issue tracker.
- `python3 "$AGENT_SKILLS_DIR/adapter-wiki/scripts/wiki.py" tools` проверяет
  живой доступ к docs wiki.

MCP-сервер в конфигурации агента не регистрируй: on-demand клиенты ходят к
шлюзу сами. Логины CLI-агентов остаются в их собственных конфигурациях, а токен
VCS-хоста его адаптер получает из CLI хостинга.
