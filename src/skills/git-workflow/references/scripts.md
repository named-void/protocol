# Скрипты и коды выхода

Все скрипты требуют bash >= 3.2 и git >= 2.31; не запускай их через `sh`.
В таблицах ниже — коды, требующие специфичной реакции вызывающего; полный
перечень кодов каждого скрипта — в его заголовочном комментарии.

Формат ключа задачи и набор типов ветки скрипты берут из окружения:
`AGENTS_KEY_PATTERN` и `AGENTS_BRANCH_TYPES` (элементы через пробел). Ключ задачи
может иметь суффикс редакции `-N`, где `N >= 2`. Без
них действуют встроенные дефолты (`^[A-Za-z][A-Za-z0-9]*-[0-9]+$` и
`feature bugfix hotfix`). Для локальной задачи `common-N` скрипты дополнительно разрешают тип
`protocol`. Вызывающий слой выставляет переменные из конфигурации
(`issue_tracker.key_pattern`, `vcs.branch_types`), чтобы валидация скриптов
совпадала с конфигом.

`AGENTS_LOCAL_ONLY=1` — работа только с локальным git-состоянием: remote `origin` не
требуется, `git fetch` не выполняется, origin-refs не опрашиваются — origin-проверки
(diverged, fast-forward, выбор `origin/<base>`) схлопываются в локальный
путь, коды 15/16 не возникают. Сверка и синхронизация с origin —
ответственность вызывающего. Флаг выставляет вызывающий слой для локальных
маршрутов; без флага отсутствие origin — ошибка среды, fetch обязателен.

## `sync-branch.sh <KEY> <type> [label]`

Синхронизирует каноническую ветку задачи с базовой и создаёт изолированный worktree. Сообщает
одну из строк:

- `created:` — каноническая ветка создана от актуальной базовой ветки (`develop`, либо `master` при разрешённом fallback для `infrastructure`);
- `switched:` — существующая каноническая ветка получила или переиспользовала worktree;
- `current:` — существующий worktree возобновлён.

Коды выхода (ненулевой код — синхронизация не завершена):

| Код | Значение |
|----|---------|
| `0` | успех (одна из строк `created:`/`switched:`/`current:`) |
| `1` | текущий каталог не git-репозиторий |
| `10` | в task-worktree есть незакоммиченные изменения отслеживаемых файлов |
| `11` | несколько канонических веток подходят под ключ |
| `12` | каноническая ветка разошлась с `origin` |
| `13` | выбранная базовая ветка разошлась с `origin` |
| `14` | целевая ветка появилась во время создания |
| `15` | remote `origin` не настроен |
| `16` | `origin` недоступен для fetch |
| `17` | базовая ветка (дефолт `develop`) отсутствует локально и на `origin`; для `infrastructure` также не найден fallback (`master`) |
| `18` | Git не смог выполнить нужный fast-forward или switch |
| `19` | изоляционный суффикс не определён (спроси агента, повтори с третьим аргументом) |
| `20` | label не соответствует формату `[a-z0-9-]+` |
| `21` | каноническая или агентская ветка занята несовместимым worktree |
| `22` | ожидаемый каталог worktree осиротел или зарегистрирован не для той ветки |
| `23` | worktree не создан |
| `64` | неверные аргументы или формат ключа |
| `65` | тип не входит в допустимый набор (`feature|bugfix|hotfix`; для `common-N` — `protocol`) |

## `accept-worktree.sh <KEY> <type> "<заголовок>" [label]`

Принимает результат агентского worktree в каноническую ветку. Коммитит агентскую ветку, переключает task-worktree на каноническую, локально сливает результат, удаляет чистый worktree и локальную агентскую ветку. Не повторяй эти шаги вручную и не используй `--force`.

| Код | Значение |
|----|---------|
| `0` | успех |
| `25` | оставляет worktree для разрешения merge-конфликта; разреши конфликт и повтори ту же команду |
| `26` | merge уже успешен, но очистка не завершена — не повторяй приёмку вслепую |
| `64` | неверные аргументы или формат ключа |
