# Скрипты git-workflow

`sync-branch.sh` и `remove-task-worktree.sh` требуют bash >= 3.2 и git >= 2.31; не запускай их через `sh`.

Формат ключа оба скрипта берут из `AGENTS_KEY_PATTERN` и `AGENTS_DERIVED_KEY_PATTERN`, набор типов ветки `sync-branch.sh` — из `AGENTS_BRANCH_TYPES`. Без них действуют `^[A-Za-z][A-Za-z0-9]*-[0-9]+$`, `^[A-Za-z][A-Za-z0-9]*(-[A-Za-z0-9]+)+-[0-9]+$` и `feature bugfix hotfix`. Ключу, не совпавшему с форматом трекера, дополнительно разрешён тип `protocol`.

`AGENTS_LOCAL_ONLY=1` разрешает работу без `origin` и пропускает fetch. Используй его только для намеренно локального проекта.

## `sync-branch.sh <KEY> <type>`

Скрипт создаёт или возобновляет одну task-ветку `<type>/<KEY>` в отдельном worktree и печатает одну строку:

- `created: <branch> (from <base>) at <path>` — новая ветка;
- `switched: <branch> at <path>` — существующая ветка получила worktree;
- `current: <branch> at <path>` — существующий worktree возобновлён.

Коды выхода:

| Код | Значение |
|---|---|
| `0` | успех |
| `1` | текущий каталог не Git-репозиторий |
| `10` | task-worktree содержит незакоммиченные изменения |
| `11` | ключу соответствуют несколько task-веток |
| `12` | task-ветка разошлась с `origin` |
| `13` | базовая ветка разошлась с `origin` |
| `15` | `origin` отсутствует без local-only режима |
| `16` | fetch `origin` не выполнен |
| `17` | базовая ветка отсутствует |
| `18` | ветку нельзя обновить |
| `21` | task-ветка занята другим worktree |
| `22` | ожидаемый путь worktree осиротел |
| `23` | worktree не создан |
| `64` | неверные аргументы или ключ |
| `65` | тип ветки не разрешён |

Любой ненулевой код блокирует Branch-Sync; не обходи отказ ручным созданием второй ветки.

## `remove-task-worktree.sh list`

Печатает по строке на каждое зарегистрированное task worktree этого репозитория: `<KEY> <clean|dirty|stash> <merged|unmerged|unknown> <path>`. Второе поле — состояние дерева, третье — влита ли его ветка в базовую ветку проекта. Статус самой задачи скрипт не знает; кандидата на уборку выбирает вызывающая сторона.

## `remove-task-worktree.sh remove <KEY> <archive-dir> [<sha256>:<path> …]`

Копирует названные evidence-файлы из дерева задачи в `<archive-dir>`, сохраняя их относительный путь, сверяет SHA-256 копии и только после этого удаляет дерево. Непроверенная копия удаляется вместе с отказом, дерево остаётся на месте. Печатает `archived: <path>` на каждый файл и `removed: <branch> at <path> (branch kept, <merge-state>)` в конце.

Ветку скрипт не удаляет никогда: `git worktree remove` уносит рабочую копию, результат держит `refs/heads/<type>/<KEY>`.

Коды выхода:

| Код | Значение |
|---|---|
| `0` | успех |
| `1` | текущий каталог не Git-репозиторий |
| `10` | дерево содержит незакоммиченные изменения |
| `11` | у ветки дерева есть stash-запись |
| `22` | ключу не соответствует зарегистрированное task worktree |
| `24` | дерево не удалено |
| `25` | скрипт запущен внутри удаляемого дерева |
| `26` | у дерева detached HEAD |
| `30` | evidence-файл отсутствует в дереве |
| `31` | SHA-256 копии не совпал с зафиксированным |
| `64` | неверные аргументы, ключ или каталог архива |

Коды `10`, `11` и `26` — человек-гейт: незакоммиченные изменения, stash и коммиты вне ветки не восстанавливаются ни веткой, ни копией evidence.
