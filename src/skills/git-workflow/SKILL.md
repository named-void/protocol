# Git workflow

Рабочее дерево, index и историю могут делить несколько сессий и человек.

1. Начиная работу, сверь `git status`. Чужие или прежние изменения не меняй
   и не включай в свой коммит.
2. Перед изменением ветки, index или worktree сверь `git status`,
   текущую ветвь, список worktree и точную цель операции.
3. Сохрани чужие изменения, index и историю. При конфликте считай базой
   уже влитые изменения целевой ветви и наложи только дельту текущей
   задачи; не выбирай сторону целиком.
4. Переключай ветвь только в чистом своём worktree. Не переноси незавершённую
   правку через `stash` ради переключения: сначала закончи и закоммить блок.
5. Для baseline-сверки не меняй общее дерево через `stash`. Текст базы читай
   через `git show <base>:<path>`, а исполняемый baseline проверяй в отдельном
   worktree.
6. Версионируемость файла проверяй в его собственном репозитории через
   `git -C <dir> ls-files -- <path>` и `git -C <dir> check-ignore <path>`:
   целевой каталог может быть вложенным репозиторием.
7. Рабочие деревья создавай соседями основного checkout. Если каталог
   перенесён, восстанови его связь командой `git worktree repair <path>` из
   основного checkout.
8. Перед коммитом сверь `git diff <path>` по каждому своему файлу, запусти
   соразмерные проверки и коммить только завершённый блок. Добавляй
   перечисленные пути через `git add <path> …`; `git add -A` не используй.
   Затем проверь `git diff --cached --stat` по всему index. Чужой hunk добавь
   отфильтрованным патчем; чужой файл временно сними через
   `git restore --staged <path>` и восстанови его index после своего коммита.

### Обязательный text-edit hook перед commit

После подготовки index выполняй перед каждым коммитом обязательный `text-edit` gate.

1. Перечитай полный текст применимого `text-edit/SKILL.md`.
2. Получи список изменённых Markdown-файлов командой `git diff --cached --name-only --diff-filter=ACMRD -- '*.md'`.
3. Перечитай полный текущий текст каждого существующего файла из списка, затем полный staged diff; для удалённых файлов проверь удаляемый текст непосредственно в diff.
4. Сверь каждый изменённый абзац и пункт с `text-edit`: если от действия зависит обязательное предусловие, начни с него; иначе начни с главного действия, сохрани одну основную мысль и одну физическую строку, удали смысловые дубли и проверь порядок предпосылок.
5. Останови коммит при нарушении правила; исправь только свои hunks, а чужие изменения оставь вне index.

9. Перед предъявлением ветви сверь `git log <base>..<branch>`: она не должна
   содержать чужих коммитов. Если база сдвинулась, повтори проверки на
   актуальной базе.

Название коммита начинай с ключа задачи из имени текущей ветки без префикса типа; одна строка не длиннее 100 символов, на русском, латиницей только идентификаторы кода, API/CLI и названия технологий.

Push, создание remote-ветви и другую внешнюю запись выполняй только по
явной команде пользователя. Для доступа к MR/PR и метаданным хоста используй
адаптер VCS.
