# Особенности Claude Code

Каналы и ограничения CLI Claude Code, которых нет у остальных исполнителей.
Факты о рабочей станции, общие для всех агентов, — `environment.md` этого же
каталога.

## Инструменты

- Auto-memory CLI упразднена:
  её отключают `autoMemoryEnabled: false` и `env.CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`
  в настройках станции — переменная читается до настройки, поэтому покрывает и
  прогон с чужим файлом настроек. Прогон без user-слоя настроек
  (`--setting-sources project`, `--bare`) получает канал снова и заводит
  `~/.claude/projects/<slug рабочего каталога>/memory`; запрет писать туда
  durable-факт — свод правил (`AGENTS.md`). Имена таких каталогов начинаются с
  дефиса, поэтому в командах передавай их после `--` или как `./<путь>`
  (`environment.md`).
- Песочница сужает `Bash`, но не инструменты правки: `Edit` и `Write` пишут
  туда, где `bash` получает `Operation not permitted`.
- Подкоманды `config` у CLI нет: `claude config …` уходит обычным prompt в новую
  сессию — тратит квоту и оставляет постороннюю запись в истории вместо вывода
  настроек. Значения читай из `settings.json`, состав ключей — из схемы в
  бинарнике или из `--help`.
- MCP-сервер браузерного расширения зарегистрирован, но подключённых браузеров
  нет (`list_connected_browsers` → `[]`): страницу гонять headless-Chrome, а не
  инструментами расширения.
- `Edit` с `replace_all: true` заменяет только точные совпадения `old_string`:
  тот же по смыслу блок с другим отступом (внутри `DO $$`, функции, вложенного
  CTE) не матчится, но отчёт всё равно говорит «All occurrences were
  successfully replaced». После такой правки подтверждай число вхождений
  `grep`, а не отчётом инструмента.
- `Read` нормализует путь лексически: `..` снимается до резолва симлинка,
  поэтому путь `~/.claude/skills/<навык>/../<каталог>/<файл>` он не находит,
  тогда как `cat` по тому же пути читает файл (проверено на обоих). Ссылку,
  выводящую за каталог навыка через `..`, в теле навыка не используй; другие
  формы относительного пути через симлинк не проверялись.
- `Read` отказывает «file unchanged since your last Read» по файлу, не читанному
  в текущем контексте: state-трекер переживает `/clear`. Не повторяй `Read` —
  читай через `cat`, а последующие правки делай по пути, который `Read` принял.
- В отдельных вызовах Bash из PATH пропадают системные каталоги: команда падает
  с `command not found: curl` (или `docker`, `sed`, `sort`) при наличии
  бинарника. Свой `export PATH=…` это не лечит, а создаёт новую поломку —
  подменяет интерпретатор (`python3` 3.9 из CommandLineTools вместо 3.14, и
  прогон краснеет `No module named 'tomllib'`, хотя код не менялся). Отказ такого
  вида считай артефактом окружения, пока не доказано обратное: повтори вызов, при
  повторе используй абсолютный путь к бинарнику, PATH не переопределяй.
- Фоновая цепочка, запущенная внутри синхронного вызова Bash как `( … & )`,
  погибает вместе с вызовом при его таймауте (проверено — файл-артефакт не создан
  и через две минуты, процесса нет). Долгие прогоны запускать
  `run_in_background: true`.
- Bash отклоняет до запуска команду вида `sleep N; <проверка>`.
  Ожидание по условию запускай `run_in_background: true` циклом до
  события с паузой; если для этой задачи есть штатный ожидатель, используй его.
- Рабочий каталог между вызовами Bash не сохраняется: после команды с `cd`
  инструмент печатает `Shell cwd was reset to …`, следующий вызов стартует из
  прежнего каталога. Каталог задавать внутри самой команды; при неожиданном
  результате проверять `pwd`, а не повторять вызов.
- Недоступность классификатора разрешений отклоняет Bash (и Edit/Skill к
  settings-файлам) с «temporarily unavailable» или «denied by classifier».
  Read продолжает работать — нужные файлы читать напрямую, блокируемую
  операцию повторить позже. `run_in_background: true` проходит, когда
  синхронный вызов блокируется. Запись allowlist обязана покрывать каждый
  сегмент составной команды: `Bash(make test *)` не покрывает `make test |
  tail`, и вся команда уходит к классификатору. Деструктивные команды к
  удалённым ссылкам (`git push --delete`) классификатор блокирует отдельно —
  нужно явное разрешение человека или запуск с префиксом `!`.
- Остаток лимитов в контекст не подмешивается; из Bash он берётся probe
  `claude -p "/usage"`: 5-часовое окно (`Current session`), недельные окна, у
  каждого — процент израсходованного и время сброса. Абсолютных чисел токенов
  вывод не даёт, оценка локальная — прогоны на других машинах в неё не входят.
  Сам probe квоту не тратит (`num_turns: 0`, нулевая стоимость), поэтому годится
  и как гейт перед дорогой фазой, и как проверка в цикле ожидания.
- Разбивку стартового контекста печатает probe `claude -p "/context"`: system
  prompt, system tools (deferred отдельной строкой — в total они не входят),
  memory files с путём и токенами каждого, skills. Вклад отдельного документа
  мерить не оценкой по символам, а этим probe: положи документ как `CLAUDE.md` в
  каталог запуска — он появится строкой `Project` в memory files. Стартовый
  контекст уменьшают `--safe-mode` (снимает memory files, навыки, hooks и MCP) и
  `--disable-slash-commands` (снимает механизм навыков); под вторым `/context`
  недоступен, и замер идёт по `usage` из `--output-format json`.
- Файл инструкций каталога Claude Code читает только под именем `CLAUDE.md`:
  каталог с одним `AGENTS.md` даёт пустые memory files, тот же файл под именем
  `CLAUDE.md` — строку `Project` (проверено). Слой, общий с codex, kilo и
  cursor, обязан нести оба имени симлинками на один файл.
- Прогон под другим сводом правил изолирует `--setting-sources project`:
  user-слой не грузится, проектный `CLAUDE.md` и `.claude/skills/*` видны,
  авторизация сохраняется (проверено — `/context` показывает в memory files
  только строку `Project`, User-навыки исчезают, сессия отвечает). Слой держи во
  временном каталоге, рабочее дерево передавай через `--add-dir`. Вместе с
  user-слоем снимаются hooks, слэш-команды и `env` из
  `$HOME/.claude/settings.json`: в таком прогоне нет алиаса `|`, а auto-memory
  включается обратно. `CLAUDE_CONFIG_DIR` для
  изоляции не годится: под ней сессия не авторизована (`Not logged in`),
  стартовый контекст пуст целиком, и это читается как достигнутая изоляция.
- Probe относится к текущему окну: замер, сделанный после сброса, о причине
  прошлого отказа не говорит. Fleet-прогон, вставший с единственной записью
  прогресса, — подпись исчерпанного лимита: проверяй квоту первой гипотезой, а
  причину, выведенную из замера в другом окне, не пиши ни в реестр сессий, ни в
  канал дефектов.
- Сессию без файла результата различай по её транскрипту: запись `assistant` с
  текстом `API Error: 529 Overloaded` — транзиентный отказ провайдера, запись
  реестра остаётся `running`, помогает повтор запуска; единственная запись
  прогресса — исчерпанный лимит; отсутствие `user`-записи с поручением —
  оборванная доставка команды вкладке.
- 5-часовое окно скользящее: время в `resets` сдвигается по мере работы
  (проверено — 1:39pm → 1:40pm за 20 с активности), поэтому ждать нужно по
  перепроверке процента, а не до однажды прочитанного времени. Пауза —
  фоновая команда `sleep` (foreground заблокирован), её завершение возвращает
  управление уведомлением; шаг 900 с даёт частые точки контроля и переживает
  сдвиг окна. Расход субагентов списывается в те же окна (`Top subagents` в
  разбивке того же вывода), отдельной квоты у них нет.
- Реестр активных сессий — `claude agents --json`: интерактивные и фоновые
  вместе, у каждой `sessionId`, `status` (`busy`/`idle`), `cwd`, `name`, у
  фоновой ещё короткий `id` — он же имя каталога в `~/.claude/jobs/`. Конец
  активности читать по статусу и исчезновению записи из реестра.
- Цель прогона задаётся командой `/goal <условие>` (работает и в `-p`), снимается
  `/goal clear`, переживает `--resume`. Механика — session-scoped Stop hook: он
  блокирует остановку и прямым текстом запрещает паузу с вопросом человеку,
  поэтому при активной цели остановка вопросом не срабатывает. Условие писать
  проверяемым и покрывающим весь объём — цель, совпадающая с темой работы,
  снимается на первой выполненной части.
- Условие цели, включающее шаг, который прогон выполнять не вправе (write во
  внешние системы, человек-гейт уровня L1), выполнено быть не может: hook будет
  требовать завершения на каждой остановке. Назови конфликт при первом
  срабатывании и дальше отвечай одной строкой, не пересказывая сделанное; снять
  цель может только человек (`/goal clear`).
- Активность цели читается из транскрипта
  `~/.claude/projects/<slug cwd>/$CLAUDE_CODE_SESSION_ID.jsonl` (id своей сессии
  CLI отдаёт этой переменной окружения) по последней записи
  `attachment.type == "goal_status"` — канал для случая, когда контекст сжат и
  сообщение об установке цели из него выпало. Четыре состояния (проверено, 2.1.220):

  | Последняя запись | Значение |
  |---|---|
  | записей нет | цель не ставилась |
  | `met: false`, `sentinel: true` | цель активна |
  | `met: true` + `reason`, `iterations`, `durationMs` (без `sentinel`) | условие выполнено, цель снята автоматически |
  | `met: true`, `sentinel: true`, без `reason` | цель снята человеком (`/goal clear`, stdout `Goal cleared: <условие>`) |

  Различать два `met: true` обязательно по `reason`: у выполнения оно есть, у
  ручного снятия нет. `claude -p "/goal"` без аргумента отвечает `No goal set`
  про новую сессию, о состоянии текущей не говорит.
- Алиас `|` навыка `self-directed` живёт в `UserPromptSubmit` hook
  `scripts/self-directed-alias.py` (регистрация — `make install`): указание
  приходит в контекст сессии, выбор маркера обоснован в README.
- Вывод `claude -p --output-format json` может начинаться строкой `Warning: no
  stdin data received in 3s, proceeding without it`, и разбор падает с
  `JSONDecodeError: Expecting value: line 1 column 1`. Вызов для машинного
  разбора запускать с `</dev/null`.
- Многоагентный workflow: сырые находки фазы поиска сохранять в durable-файл
  сразу по завершении фазы, а не в конце прогона, и разносить поиск с
  верификацией по отдельным прогонам — лимит сессии убивает прогон целиком, и
  результаты остаются только в `journal.jsonl`. Смена модели субагентов общий
  лимит не обходит.
