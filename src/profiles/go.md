# Go

- Проверяй shadowing, особенно `err`; при риске запускай доступный shadow analyzer.
- При сканировании `rows` в цикле не устраняй shadow внешнего `err` заменой на `err =` (ловит gocritic `sloppyReassign`) и не объявляй `err :=` в одном scope с внешним `err` (ловит govet `shadow`): выноси цикл в отдельную scan-функцию (образец — `scanSourceListItemRows`).
- В generic validation APIs явно указывай type parameters, если inference нестабилен или ухудшает IDE/readability.
- Следуй logging-паттерну проекта; для нескольких сообщений один раз вычисляй общий logger с контекстом и operation name и переиспользуй его.
- Doc-комментарии к экспортируемым функциям, методам и типам пиши на русском в godoc-форме, начиная с имени объявления; package comment по умолчанию не обязателен — добавляй только при неочевидном назначении пакета. Поддерживай конвенцию вручную и не полагайся на линт — правило revive `exported` в проектах отключено или не настроено.
- `_test.go` исключай из ручной проверки godoc для экспортируемых объявлений: комментарии для `Test...`, test doubles и mock/stub методов не требуются, если нет отдельной причины.

## Прогон проверок

- Активный `go version` должен соответствовать directive `go` в `go.mod`. `panic: file requires newer Go version` от golangci-lint означает несовместимость тулчейна, а не дефект кода, если `go build` и `go test` проходят.
- Прогон проверок начинай с `go test ./...`; `go test -race ./...` добавляй,
  когда diff затрагивает конкурентность. Запускай из корня модуля.
- Недоступный кэш сборки или модулей (нет прав, изолированная песочница) —
  направь `GOCACHE`/`GOMODCACHE` внутрь checkout и повтори прогон.
- Недоступный `proxy.golang.org` не блокирует работу с уже закэшированными
  модулями: `GOFLAGS=-mod=mod GOPROXY=off go get` проходит офлайн.

## Тесты: mockery + testify

- Моки не пиши руками: генерируй mockery по `//go:generate` рядом с интерфейсом; ассерты — testify (`require` для прерывающих проверок, `assert` для сравнений). Для неэкспортируемого интерфейса директиве обязателен `--exported`, иначе мок в пакете `mocks` будет недоступен.
- Создавай моки конструкторами `mocks.NewXxx(t)`: они регистрируют `AssertExpectations` в cleanup, а неожиданный вызов фейлит тест — «метод не должен вызываться» выражай отсутствием `.On(...)`, без отдельных проверок.
- Прозрачный transaction manager мокай `.On("WithinTransaction", mock.Anything, mock.Anything).Return(func(ctx context.Context, fn func(context.Context) error) error { return fn(ctx) })`; проверку «вызов внутри транзакции» — маркером в context внутри этой функции и `mock.MatchedBy` на ctx-аргументе ожиданий.
- В ожиданиях typed nil передавай явно, например `(*uuid.UUID)(nil)`: литеральный `nil` не заматчит типизированный nil-указатель.
- Аргументы в `.Run`-капчурах доставай двухзначной type assertion с проверкой `ok` — errcheck с `check-type-assertions` расценивает однозначную как ошибку.
- В table-driven тестах моки, чьё поведение не зависит от кейса (транзакция, сопутствующие репозитории/чекеры без `.On(...)`), создавай один раз перед циклом; внутри `t.Run` заводи только то, что varies по кейсу. `t.Parallel()` в subtest это не ломает: cleanup мока привязан к родительскому `t`, который дожидается завершения всех subtests.

## Локальный запуск

- Для локального запуска или debug в IDE скопируй `profiles/assets/debug.go` этого репозитория в каталог main-пакета приложения: файл в `init()` загружает `.env` и сообщает о ключах из `.env.example`, отсутствующих или пустых в окружении. Не коммить его в проект, если проект не договорился об обратном.

## GUI на Ebiten: проверка без человека (macOS)

- Бинарь собирай и запускай из своего рабочего каталога (scratchpad) с
  `EBITEN_SCREENSHOT_KEY=q`: скриншот пишется в рабочий каталог процесса, имя
  уходит в stdout строкой `Saved screenshot: …`.
- Нажатия подавай одним `osascript -e 'tell application "System Events" …'`:
  `key code N` — короткое нажатие, `key down N` / `key up N` — удержание,
  паузы — `delay` внутри того же скрипта.
- `glfw: Cocoa: Cannot query content scale without screen` в логе — не отказ:
  окно и рендер работают.
- Кадр за пределами стартового состояния снимай на probe-копии репозитория
  (например с укороченной картой), исходники проекта для этого не меняй.
- Прогон с cgo-зависимостями печатает предупреждения clang из чужих пакетов:
  вывод фильтруй по путям своего модуля.
