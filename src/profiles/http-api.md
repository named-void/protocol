# HTTP/API

- Без явного требования возвращать полную модель держи write API минимальными: create возвращает `id`, update/save/delete — `204 No Content`, актуальное состояние читается отдельным GET.
- Для известных resource-сценариев возвращай доменно-конкретные not found ошибки вместо общего сообщения, если это помогает клиенту определить отсутствующую сущность.
- В request/query binding принимай только документированные имена параметров; для новых и изменяемых query-параметров используй snake_case и не добавляй camelCase/legacy aliases без явного требования. При удалении alias синхронизируй код, тесты и локальную документацию.
- Валидацию JSON-тела держи целиком на binding-тегах через `httperrors.BindJSON` — отдельного ручного post-bind слоя (`validate*Request`) не заводи. BindJSON обрезает краевые пробелы в строках и валидирует до передачи в usecase. Присутствие/непустоту/длину задавай стандартными тегами (`required`; непустота — `notblank`, не `min=1`; длина — `min`/`max`). Формат (символы, телефон, email, URL, цифровые реквизиты) и кросс-полевые правила тоже задавай тегами: встроенными (`oneof`, `required_without` и т.п.) или кастомными валидаторами, зарегистрированными в `binding_validation.go`; код и текст ответа для кастомного тега задаёт `fieldErrorMapper`. Имя поля в тексте ошибки не дублируй — клиент видит его из JSON-пути в `field`. Query-параметры и заголовки binding-тегами не покрываются — их валидируй вручную.
- Ожидание HTTP-теста задавай точным кодом ответа и наблюдаемым эффектом (достигнутый вызов слоя, изменённое состояние), а не отрицанием кода: ассерт «код не 400» удовлетворяется любым отказом, включая 500 от паники в обработчике, и остаётся зелёным при полностью сломанном пути. Стенд собирай с рабочим usecase на моках; роутер с `nil`-зависимостью проверяет только binding, и проверки на теле ответа сверяются с пустой строкой.
- Обязательность поля в swagger (`required`) swaggo выводит из тега `binding:"required"`, а не из `json`-тега (проверено `make swagger`): finding вида «`omitempty` скрывает обязательность в swagger» неверен по обоснованию. Но `omitempty` на required-поле снимай всё равно — по другой причине: при сериализации он выкидывает нулевое значение (`0`, `""`, `false`, `nil`) из ответа, и обязательное поле с легитимным нулём молча исчезает из payload. Итог: обязательность задаёт `binding:"required"`, а `omitempty` на required-полях не оставляй.
