# Интеграции rpay

Проза проекта rpay: участники интеграции, раскладка каталогов и источники
работы. Подключается к работе по `profile_rules` карты проекта для путей под
`integrations/`. Общие требования свода правил и навыков маршрута здесь не
повторяются.

## Участники и маршрут платежа

- Сайт мерчанта подключён к площадке клиента — платёжной компании.
- Платёжная компания выступает процессором и подключает банки через гейты или
  каналы; наше программное обеспечение она арендует.
- Маршрут платежа: сайт мерчанта → процессор → Connect Gateway → гейт.
- Интеграция каждого гейта работает в отдельном стеке или контейнере: к
  процессору контейнер обращён протоколом Connect Gateway, к провайдеру —
  протоколом своего гейта.
- Нормативная документация Connect Gateway — https://book.reactivepay.com/en.
  Документация https://developer.xpate.com/reference/introduction относится
  только к XPAY и на другие гейты не переносится.

## Раскладка

Каждая интеграция — каталог `integrations/<имя>` с тремя папками:

- `wiki/` — спецификации провайдера и зафиксированные решения по интеграции;
- `tasks/` — задачи интеграции, файл на задачу;
- `src/` — код интеграции.

Первая интеграция — `integrations/moneliq`.

## Источники работы

- Задачу бери файлом из `tasks/` соответствующей интеграции: внешнего трекера
  нет (`issue_tracker.product = "none"`), путь к файлу передаёт поручение.
  Статусы наружу не читаются и не пишутся, вопросы `needs-info` задавай
  человеку в сессии.
- Ключ задачи — `<ИНТЕГРАЦИЯ>-<номер>` заглавными (`MONELIQ-1`); он же имя
  файла задачи и основа имени ветки.
- Спецификацию бери файлами из `wiki/` той же интеграции: адаптер `docs-wiki`
  не сконфигурирован, spec-дискавери по внешней wiki не выполняется. В
  `Sources` карточки называй путь файла и дату чтения.

## Код и git

- Все интеграции ведёт один git-репозиторий уровня `rpay`: карта проекта, эта
  проза, `wiki/`, `tasks/` и `src/` каждой интеграции версионируются вместе.
- Внешнего remote у него нет — вызовы скриптов `vcs-host` делай с
  `AGENTS_LOCAL_ONLY=1`, MR-маршрут не применяется.
- Задача работает в своём worktree от канонической ветки `<type>/<KEY>`,
  база — текущая ветка репозитория `rpay`.

## Новая интеграция

Создай `integrations/<имя>/{wiki,tasks,src}`. Карту проекта правь только если у
интеграции появляется внешняя система: свои значения адаптеров она не
объявляет.
