# Шаблон комментария для QA

Форма комментария для QA в задачах UPL. Обязательность, момент сборки, состав и
запрет на координаты кода заданы навыком (`protocol`, раздел «Комментарий для
QA»); здесь — только разметка и правила её заполнения. Прочитай шаблон перед
сборкой и сверь с ним готовый текст.

```text
**Стенд:**
Develop

**Изменения:**
1. Доработаны методы
[GET] /api/v1/resource - добавлена фильтрация по `status`; в ответ добавлено поле `owner_name`.

2. Добавлены методы
[GET] /api/v1/resource/slim - возвращает сокращённый список и фильтрует его по части имени.

3. Удалены методы
[DELETE] /api/v1/resource/\{id} - удалён из внешнего контракта.
```

- Заголовки оформляй жирным через `**…**`. Markdown-заголовки (`#`, `##`), таблицы (`|…|`) и списки-звёздочки не используй — комментарий вставляется в трекер как есть.
- Текст начинается ровно с `**Стенд:**` и следующей строки со стендом; затем `**Изменения:**`. Своих заголовков, групп и секций сверх шаблона не добавляй.
- Стенд не указан — пиши `Develop`.
- Метод пиши как `[METHOD] /path`.
- Параметр пути в фигурных скобках экранируй обратным слэшем перед `{` (`/path/\{id}`): иначе wysiwyg-редактор трекера принимает `{...}` за макрос и рвёт строку визуально.
- Оставляй только непустые группы `Доработаны методы`, `Добавлены методы`, `Удалены методы`; нумерация идёт по оставшимся.
- Несовместимое изменение помечай префиксом `breaking:`.
- Формулировки краткие, без слов-филлеров («по-прежнему», «и т.п.») и вводных конструкций без смысловой нагрузки.
- Недостаточно подтверждённые детали выноси после всех разделов отдельной строкой `Нужно уточнить:`.
